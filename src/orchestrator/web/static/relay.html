      The crew

      Every robot runs the same AI model, but each gets its own job description and its own set of tools. Only the Builder can change files. For bug-fixing jobs, the Builder is called the Coder and the Checker is called the Tester.

      A job moves from left to right, and each robot leaves a short note for the next one. If the project has its own tests, they run after the Builder with no AI involved. If they fail, if the Checker finds a broken item, or if the Reviewer finds a real problem, the folder goes back to the Builder with notes, up to three rounds in total.

      Does a team beat one robot?

      15 bug-fixing tasks with hidden tests, 3 runs each, the same model (gpt-oss-120b) for both. A run passes only if the project's visible and hidden tests pass afterwards.

      Where the team's tokens went

      Average per task: 47,932 tokens for the team, 11,459 for one robot.

      The whole difference is one task

      The two modes tied on 14 of 15 tasks. On the dynamic programming task, one robot fixed the bugs the tests exposed and stopped, in all three runs. A rule written only in the code's documentation (return -1 when an amount cannot be made) was never applied.

      Planning made the difference

      The Planner read that rule and wrote it down as a requirement. Once it was on the task board, the Coder handled it every time.

      The checking loop never fired

      Every team run finished in the first round. The Tester never reported a failure and the Reviewer approved every fix, so on these tasks checking added cost but changed no outcome.

      The Tester often ran out of time

      It used the most tokens of any robot and failed to hand in its report in 64% of runs, because it checked items one at a time. It now checks several per step; a new run will show whether that worked.

      About four times the cost

      The team used 4.2 times the tokens and 2.6 times the time of one robot.

      Run it yourself

      For developers: Relay runs on your own computer with your own AI key. You need Python 3.11 or newer and a key for any OpenAI-compatible provider (Groq has a free tier).

      Get the code

      git clone https://github.com/Muhammad-Aitzaz-Khan/agent-orchestrator.git cd agent-orchestrator python -m venv .venv .venv\Scripts\activate pip install -e ".[dev]"

      Add your key

      copy .env.example .env python -m orchestrator.doctor

      Put the key in .env. The doctor checks that the model can call tools.

      Open the office

      python -m orchestrator.web
